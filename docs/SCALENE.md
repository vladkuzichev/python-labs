Додавання NumPy не змінює базовий скорер: він збережений як контроль. Профілі index/load виконують базові функції, незалежно від наявності нового векторного шляху. Контрольний запуск Scalene через Python subprocess повернув код 0 та зберіг валідний JSON із ненульовими семплами. Діагностика stderr у PowerShell не використовувалася як заміна цього коду.

## Додаткова перевірка під час повторної перевірки

Попередні числа вище не змінено. Додатковий запуск Scalene 2.4.0 на CPython 3.13.18 / Windows 11 виконав 50 побудов того самого корпусу з program-path=корінь та sampling-rate=0.005; exit 0. Це окремий повтор базового index-коду після вихідного досліду, не профіль до першої оптимізації.

| Функція | Python, % | Native, % | System, % |
|---|---|---|---|
| iter_documents | 13.155933 | 67.251629 | 12.302823 |
| build_index | 0.047031 | 2.583897 | 0.294038 |

[Повний додатковий JSON](scalene-index-audit.json), [команда/середовище](evidence/scalene-index-audit-summary.json). Tokenize знову не отримав окремого семпла. Не можна прирівнювати відсутність семпла до нульового часу або вигадувати точну Python/native частку. Вибіркова атрибуція Windows не закриває цей пункт повністю.
