# Версії findex

## Документація та запуск

Уточнено встановлення після clone, походження даних, докази CI, матеріали Reflection/здачі, обмеження історичних тегів і окреме постачання звітів. Dockerfile тепер будує дані з коду, а не потребує відсутніх у Git COPY-джерел. Старі теги та числа вимірювань не змінено.

## lab-08

Профілювання, NumPy та семантичний пошук. Вимірювання — медіани 100 прогрітих запусків без побудови індексу й без снипетів. NumPy виграє на довгих списках, але програє на рідкому терміні через наклад виклику масивних операцій. Збережений NPZ містить лише числові масиви й JSON; allow_pickle=False. MiniLM є реальною локальною ONNX-моделлю, а не заміною на випадкові вектори. Вектори фрагментів L2-нормовано; оцінка документа — найкращий фрагмент; RRF зливає ранги з константою 60.

## lab-07

Вебпошук: FastAPI, Pydantic та вебінтерфейс. oha 1.16.0 надсилав по 1000 справжніх HTTP-запитів з concurrency=50. Окремий дослід надсилав 20 запитів одночасно через httpx. Для oha SSL_CERT_FILE указував на certifi, оскільки читання системного сховища сертифікатів було недоступне; налаштування Windows не змінювалися. Чотири процеси розділяють GIL, але кожен завантажує власний індекс.

## lab-06

Асинхронний краулер: asyncio. Джерело — власне локальне дзеркало scripts/mirror.py, а не сторонній сайт. Модель I/O явно містить затримку 15 мс, per_host=20 та мінімальну паузу 2 мс. Усі три конфігурації збирали по 200 сторінок з тієї самої початкової адреси. HTTP 429 із Retry-After=0 повторено успішно; це видно в crawl.log. RSS семплувався після сторінок. Concurrency=5 виявилася швидшою за 20; універсального виграшу 20 не стверджується.

## lab-05

Конкурентність і GIL: потоки, процеси та паралельна індексація. Кожна клітинка містить медіану щонайменше трьох запусків на повному корпусі. CPU для процесів включає батьківський процес та виміряний CPU воркерів; RSS стосується лише батька. У 3.13t RSS відстежував окремий звичайний Python, тому вільнопотоковий процес не імпортував розширення, здатні ввімкнути GIL. Потоки 3.13t перевірено з sys._is_gil_enabled() == False. У рядках serial N означає число послідовно оброблених частин, а не одночасні потоки.

## lab-04

Типи, тестування, пакування і CLI. Публічні функції типізовано; рушії мають Literal у внутрішньому API та Enum на межі Typer. Протокол Scorer не потребує успадкування. JSON Lines надходять лише у stdout; діагностика — stderr. Зібраний wheel перевірено встановленням через uv tool в окреме середовище. Згодом підтверджено успішний GitHub Actions №43021534036 для фінального b02d1be; це не окремий історичний запуск на lab-04.

## lab-03

Ранжування і модель об’єктів: протоколи, декоратори та мова запитів. Парсер будує дерево з пріоритетом NOT > AND > OR; суміжні терміни означають AND. Фраза перевіряється за суміжними позиціями. BM25 нормалізує довжину й насичує TF, а TF-IDF використовує логарифмічний TF. Результати впорядковано за score і doc_id. P@5 обчислено за неповною розміткою; незалежну перевірку людиною не виконано. Три sanity-check додатково обчислено на документах повного корпусу. Для насичення використано реальний документ з TF≥20 та незмінними IDF/довжиною, обмежуючи враховані входження до 1, 2, 19, 20; це контрольний розрахунок скорера, а не зміна корпусу.

## lab-02

Інвертований індекс: словники, хешування та пам’ять. Постінги будуються за один прохід і сортуються за doc_id. Slots усуває словник атрибутів кожного об’єкта; array зберігає сирі числа без окремих об’єктів int. На частих термінах set виграв у merge; на рідких списках наклад set більший. Pickle придатний тільки для власних довірених індексів; JSON не виконує код.

## lab-01

Ітератори, генератори та корпус документів. Потік iter_documents відкриває один файл або один запис JSONL за раз. Counter є накопичувачем результату; його пам’ять зростає зі словником, а не з усім корпусом. Жадібна версія додатково утримує всі тексти та списки токенів. Обидва шляхи дали однакову статистику.
